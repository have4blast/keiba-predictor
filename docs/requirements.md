# 要件定義 — 競馬予想AI

## 1. 機能要件 (Functional Requirements)

### FR-01: データ収集
| ID | 要件 | 優先度 |
|----|------|-------|
| FR-01-1 | netkeiba.com から過去レース結果を一括スクレイピングできる | 必須 |
| FR-01-2 | 翌日の出走予定レース・馬情報を取得できる | 必須 |
| FR-01-3 | 馬プロフィール（血統・性別・生年月日）を取得できる | 必須 |
| FR-01-4 | 騎手プロフィール・過去成績を取得できる | 必須 |
| FR-01-5 | 調教師プロフィール・過去成績を取得できる | 必須 |
| FR-01-6 | レースごとの上がり3Fタイム・ラップタイムを取得できる | 必須 |
| FR-01-7 | 単勝・馬連・3連複オッズを取得できる | 必須 |
| FR-01-8 | スクレイピングを中断・再開（--resume）できる | 必須 |

### FR-02: データ永続化
| ID | 要件 | 優先度 |
|----|------|-------|
| FR-02-1 | SQLite データベースに全データを格納する | 必須 |
| FR-02-2 | 同一IDのデータを upsert（重複なし）で保存する | 必須 |
| FR-02-3 | 出走予定レースは finish_position=NULL で格納する | 必須 |

### FR-03: 特徴量エンジニアリング
| ID | 要件 | 優先度 |
|----|------|-------|
| FR-03-1 | 馬関連特徴量を計算する（馬齢・血統・脚質・競走間隔等13項目） | 必須 |
| FR-03-2 | 騎手関連特徴量を計算する（コンビ成績・コース適性等7項目） | 必須 |
| FR-03-3 | 調教師関連特徴量を計算する（勝率・コース適性等6項目） | 必須 |
| FR-03-4 | レース条件特徴量を計算する（天候×馬場・枠番・グレード等7項目） | 必須 |
| FR-03-5 | オッズ・市場特徴量を計算する（人気順位・変動率等4項目） | 必須 |
| FR-03-6 | 相対・統計加工特徴量を計算する（レース内相対評価等5項目） | 必須 |
| FR-03-7 | 馬間インタラクション特徴量を計算する（直接対決・血統相性等5項目） | 必須 |
| FR-03-8 | 全ローリング特徴量に shift(1) を適用しデータリークを防止する | 必須 |
| FR-03-9 | 特徴量を Parquet 形式で保存する | 必須 |

### FR-04: モデル学習
| ID | 要件 | 優先度 |
|----|------|-------|
| FR-04-1 | LightGBM で勝利予測モデルを学習できる | 必須 |
| FR-04-2 | LightGBM で複勝予測モデルを学習できる | 必須 |
| FR-04-3 | GroupKFold(groups=race_id) による時系列クロスバリデーションを行う | 必須 |
| FR-04-4 | 学習後に ROI・的中率を evaluation レポートとして出力する | 必須 |
| FR-04-5 | モデルを pkl ファイルとして保存・読み込みできる | 必須 |

### FR-05: 予測
| ID | 要件 | 優先度 |
|----|------|-------|
| FR-05-1 | 出走予定馬の特徴量を生成して予測スコアを付与できる | 必須 |
| FR-05-2 | 予測時にエンコーダを再フィットしない（学習時のエンコーダを使用） | 必須 |
| FR-05-3 | 各馬に勝率・複勝率スコアを付与して降順ソートできる | 必須 |

### FR-06: ダッシュボード
| ID | 要件 | 優先度 |
|----|------|-------|
| FR-06-1 | 今日/明日の予測結果を一覧表示できる | 必須 |
| FR-06-2 | バックテストのROI曲線・成績グラフを表示できる | 必須 |
| FR-06-3 | スクレイピング進捗・DB状況を確認できる | 必須 |
| FR-06-4 | 特徴量重要度（SHAP）を可視化できる | 推奨 |
| FR-06-5 | レース選択・馬選択のフィルタリングができる | 推奨 |

---

## 2. 非機能要件 (Non-Functional Requirements)

### NFR-01: パフォーマンス
| ID | 要件 |
|----|------|
| NFR-01-1 | スクレイピング間隔: 2〜3.5秒/リクエスト |
| NFR-01-2 | 1レース分の予測処理: 5秒以内 |
| NFR-01-3 | 特徴量生成（全データ）: 10分以内（1年分） |
| NFR-01-4 | モデル学習（1年分データ）: 30分以内 |

### NFR-02: 信頼性
| ID | 要件 |
|----|------|
| NFR-02-1 | スクレイピング失敗時にエラーログを出力してスキップ（中断しない） |
| NFR-02-2 | DB書き込みは upsert で冪等性を保証 |
| NFR-02-3 | --resume フラグで中断再開可能 |

### NFR-03: 保守性
| ID | 要件 |
|----|------|
| NFR-03-1 | loguru による構造化ログ出力 |
| NFR-03-2 | 関数シグネチャに型ヒントを付与 |
| NFR-03-3 | 各モジュールは単一責任の原則に従う |

### NFR-04: セキュリティ・コンプライアンス
| ID | 要件 |
|----|------|
| NFR-04-1 | User-Agent ヘッダーを設定してリクエストを送信する |
| NFR-04-2 | API キー等の機密情報は .env ファイルで管理（ハードコード禁止） |
| NFR-04-3 | netkeiba.com の利用規約を遵守した頻度でアクセスする |
