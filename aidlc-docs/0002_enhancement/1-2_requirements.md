# 要件定義 — 第2サイクル (0002_enhancement)

## 背景

第1サイクルで競馬予想AIの基盤（スクレイピング・特徴量・LightGBM・Streamlit）を構築した。  
第2サイクルでは **モデル精度の向上** と **スクレイパーの運用安定性向上** を図る。

---

## A. モデル精度改善 — 機能要件

| ID | 要件 | 優先度 |
|----|------|--------|
| A-FR-01 | SHAP 値を計算し、レース毎の予測根拠を上位10特徴量で可視化する | 高 |
| A-FR-02 | ダッシュボードの予測結果ページに SHAP 棒グラフを表示する | 高 |
| A-FR-03 | Optuna で LightGBM ハイパーパラメータを自動最適化するスクリプトを追加する | 中 |
| A-FR-04 | チューニング結果を `models/tuning_report.json` に保存し再現性を確保する | 中 |
| A-FR-05 | 上がり3F偏差特徴量（レース内相対）を `relative_features.py` に追加する | 高 |
| A-FR-06 | ペース係数（前半/後半ラップ比）を `race_features.py` で改良する | 中 |
| A-FR-07 | 斤量×距離 交差特徴量を `interaction_features.py` に追加する | 低 |

## A. モデル精度改善 — 非機能要件

| ID | 要件 |
|----|------|
| A-NFR-01 | SHAP 計算は `@st.cache_data(ttl=600)` でキャッシュし UI 応答 3 秒以内 |
| A-NFR-02 | Optuna チューニングは `--trials 50` をデフォルトとし 10 分以内に完了 |
| A-NFR-03 | 新特徴量追加後も既存 Parquet スキーマとの後方互換を `encoder.py` で保証 |

---

## C. スクレイパー堅牢化 — 機能要件

| ID | 要件 | 優先度 |
|----|------|--------|
| C-FR-01 | CSS セレクタが変更された場合に複数セレクタ候補を順に試すフォールバック機構を実装する | 高 |
| C-FR-02 | スクレイプ結果の欠損率・値域を自動検証する `db/validator.py` を追加する | 高 |
| C-FR-03 | 検証失敗時は `logs/validation.log` に警告を出力し処理を継続する（中断しない） | 高 |
| C-FR-04 | 調教タイム（最終追い切り・コース・タイム）を取得する `scraper/training_time.py` を追加する | 中 |
| C-FR-05 | 調教タイムを `race_entries` または新テーブル `training_times` に格納する | 中 |
| C-FR-06 | `scripts/validate_data.py` で DB 全体の品質レポートを出力する CLI を追加する | 中 |

## C. スクレイパー堅牢化 — 非機能要件

| ID | 要件 |
|----|------|
| C-NFR-01 | フォールバック試行はログに記録し、どのセレクタが使われたか追跡可能にする |
| C-NFR-02 | バリデーターは既存スクレイピングフローを一切変更せず後付けで呼び出せること |
| C-NFR-03 | 調教タイムスクレイパーは既存の `RateLimitedSession` を再利用すること |

---
